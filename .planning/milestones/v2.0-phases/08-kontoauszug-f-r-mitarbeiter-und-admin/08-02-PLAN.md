sie zeigt lediglich, was der Server freigibt.

GET /api/vacation-transactions?userId=<n>&year=<n>&limit=<n>

  - `userId` nur für Admins wirksam; ein Mitarbeiter, der eine fremde `userId` sendet,
    erhält 403 (kein stiller Rückfall auf das eigene Konto)
  - `year` optional, Standard: laufendes Jahr
  - `limit` optional, Standard 200, Obergrenze 500

  Antwort: ApiResponse<VacationAccountStatement>

  VacationAccountStatement {
    userId: number
    year: number
    entitlement: number
    carryover: number
    taken: number
    available: number        // entitlement + carryover − taken  → identisch mit der Spalte
                             //   „Verbleibend" der Urlaubsliste
    journalBalance: number   // Summe aller days des Jahres
    transactions: VacationJournalEntry[]
  }

  VacationJournalEntry {
    id: number
    userId: number
    year: number
    date: string                 // YYYY-MM-DD
    type: 'entitlement' | 'carryover' | 'vacation_taken' | 'vacation_reverted' | 'correction' | 'expiry'
    days: number                 // positiv = Gutschrift, negativ = Verbrauch
    description: string | null
    referenceType: 'absence' | 'manual' | 'system' | null
    referenceId: number | null
    balanceBefore: number | null
    balanceAfter: number | null  // laufender Saldo nach dieser Buchung
    createdAt: string
    createdBy: number | null
    absence: {
      id: number
      type: string               // 'vacation' | 'sick' | 'unpaid' | 'overtime_comp'
      startDate: string
      endDate: string
      status: string             // 'pending' | 'approved' | 'rejected'
      days: number
    } | null
  }

  Sortierung: date ASC, id ASC (Storno steht nach der Genehmigung, die er aufhebt)
