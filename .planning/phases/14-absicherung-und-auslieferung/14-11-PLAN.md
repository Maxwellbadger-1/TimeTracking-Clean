kaputtgeht, wenn er übersprungen wird — ein vorhandenes `latest.json` sagt nichts darüber, ob
es alle Plattformen enthält.

lesen und einzeln belegen:
- Feld `version` ist `1.9.0`

vorhanden". Fehlt ein Schlüssel oder eine Signatur, ist das Release für die betroffene
Plattform kaputt: Befund festhalten, Plan als blockiert melden.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tag-Push → GitHub Actions → veröffentlichtes Release | Ab der Veröffentlichung ziehen installierte Apps das Update automatisch |
| `latest.json` → Auto-Update installierter Apps | Ein fehlender Plattformschlüssel legt das Auto-Update für alle Anwender dieser Plattform still |
| Release-Notes → Öffentlichkeit | Der Text ist für jeden mit Repository-Zugriff sichtbar |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-65 | Denial of Service | Auto-Update installierter Apps | mitigate | `latest.json` wird heruntergeladen und **je Plattformschlüssel einzeln** auf gesetzte `url` und `signature` geprüft; zusätzlich eine HTTP-200-Stichprobe auf eine der URLs. Keine Sammelaussage „alle vorhanden". |
| T-14-66 | Tampering | uneinheitliche Version | mitigate | Alle drei Dateien werden einzeln per `grep` auf `1.9.0` geprüft und zusätzlich negativ auf verbliebenes `1.8.0` in der jeweiligen `version`-Zeile. |
| T-14-67 | Spoofing | doppeltes oder fremdes Release | mitigate | Kein manuelles `gh release create`; das Release entsteht ausschließlich über `tauri-action` mit `releaseDraft: false`. Die Abweichung von der Anleitung in `.claude/CLAUDE.md` wird im Protokoll begründet. |
| T-14-68 | Information Disclosure | Release-Notes und CHANGELOG | mitigate | Die Notes beschreiben Funktionen in Anwendersprache; keine Nutzer-IDs, keine Namen aus dem realen Umstellungsfall, keine Serveradressen, keine Zugangsdaten. Vor dem Commit gegenlesen. |
| T-14-69 | Tampering | Auslieferung eines ungeprüften Stands | mitigate | Die vier Gates laufen **vor** dem Tag; `git status --porcelain` muss leer sein, damit nichts Ungetestetes mitgeht. Das Release liegt nach der Produktionsverifikation (D7). |
| T-14-70 | Repudiation | „Release ist durch" ohne Beleg | mitigate | Workflow-Lauf-Id, Job-Conclusions, Artefaktliste und der plattformweise `latest.json`-Befund werden wörtlich protokolliert. |
| T-14-SC | Tampering | npm/pip/cargo installs | mitigate | Dieser Plan installiert lokal kein Paket und ändert keine Abhängigkeit. Die Änderungen an `desktop/package.json` betreffen ausschließlich das Feld `version`; vor dem Commit prüfen, dass `git diff desktop/package.json` nur diese eine Zeile zeigt. |
</threat_model>
