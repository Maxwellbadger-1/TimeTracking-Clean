<objective>
Der Server liefert den Urlaubs-Kontoauszug — und lässt niemanden in ein fremdes Konto sehen.

Zweck: Das Journal existiert seit Phase 5–7 und ist seit dem Backfill vollständig (52 Buchungen
in Produktion). Sichtbar ist es bisher nur über die Datenbank. Dieser Plan macht es über eine
API zugänglich und verankert die Zugriffsregel dort, wo sie nicht umgangen werden kann: im
Server, nicht in der Oberfläche (REQ-14).

Ergebnis: `GET /api/vacation-transactions` mit Rollenprüfung, Jahresfilter und mitgelieferten
Antragsdaten für die Verlinkung; dazu die Schließung einer bestehenden Lücke am Endpunkt
`GET /api/vacation-balances/:userId`, der heute jedem angemeldeten Nutzer das Konto jedes
anderen ausliefert.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Desktop-Client → Express-API | Jeder Query-Parameter (`userId`, `year`, `limit`) ist nicht vertrauenswürdig; die Rolle stammt ausschließlich aus der serverseitigen Session, niemals aus dem Request-Körper |
| Express-API → SQLite | Alle Werte gehen ausschließlich über Prepared Statements in die Datenbank |
| Angemeldeter Mitarbeiter → Daten anderer Mitarbeiter | Urlaubsdaten sind personenbezogen; die Rollengrenze verläuft innerhalb der authentifizierten Nutzerschaft |
