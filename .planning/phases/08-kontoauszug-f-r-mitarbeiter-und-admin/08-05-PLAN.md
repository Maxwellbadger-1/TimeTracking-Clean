    Tag `v1.8.0` auf dem Commit aus Task 1 setzen und nach `origin` pushen
    (`git tag v1.8.0 && git push origin v1.8.0`).

    Kein vorheriges `gh release create`: `tauri-action` legt das Release im Workflow selbst an —
    die bestehenden Releases tragen alle den generierten Namen `TimeTracking System v<Version>`.
    Ein manuell vorab erzeugtes Release würde diesen Namen überschreiben und die vier
    Matrix-Jobs müssten sich auf ein fremd erzeugtes Ziel einigen.

    Fehlerursache über `gh run view <run-id> --log-failed` zu ermitteln — ein unvollständiger
    Satz Artefakte ist kein gültiges Release, weil `latest.json` dann Plattformen auslässt.

    - Kein Matrix-Job des Laufs steht auf `failure`: `gh run view <run-id> --json jobs --jq '[.jobs[].conclusion] | unique'` ergibt `["success"]`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Git-Tag → GitHub Actions → Release-Artefakte | Der Tag löst einen Build aus, dessen Ergebnis auf Anwenderrechner installiert wird |
| Release-Artefakte → Auto-Update der installierten Anwendungen | `latest.json` steuert, welche Datei die Anwendung herunterlädt und installiert |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-40 | Tampering | Untergeschobenes Update-Artefakt | mitigate | `tauri-action` signiert die Updater-Artefakte mit `TAURI_SIGNING_PRIVATE_KEY` aus den GitHub-Secrets; die Prüfung fordert für jeden Plattformschlüssel in `latest.json` ein gesetztes `signature`-Feld |
| T-08-41 | Denial of Service | Unvollständige `latest.json` bricht das Auto-Update einer Plattform | mitigate | Acceptance Criterion prüft alle vier Schlüssel einzeln; bei einem fehlenden Schlüssel wird der Matrix-Job wiederholt statt das Release zu melden |
| T-08-42 | Tampering | Versionsdrift zwischen den drei Versionsdateien und dem Tag | mitigate | Drei getrennte `grep`-Prüfungen auf `1.8.0` plus Gegenprüfung, dass `1.7.3` nicht mehr vorkommt; zusätzlich muss `latest.json` die Version `1.8.0` tragen |
| T-08-43 | Elevation of Privilege | Release-Workflow mit Schreibrechten auf das Repository | accept | `permissions: contents: write` ist für die Veröffentlichung erforderlich und auf den Release-Job begrenzt; bestehende, unveränderte Konfiguration |
| T-08-SC | Tampering (Supply Chain) | `npm install` im Release-Workflow | accept | Der Workflow führt `cd desktop && npm install` gegen das bestehende, unverändertes `package.json` aus; dieser Plan fügt keine Abhängigkeit hinzu. Kommt wider Erwarten ein Paket hinzu, ist vor der Installation ein blockierender Human-Checkpoint mit Prüfung auf `npmjs.com/package` einzulegen |
</threat_model>
