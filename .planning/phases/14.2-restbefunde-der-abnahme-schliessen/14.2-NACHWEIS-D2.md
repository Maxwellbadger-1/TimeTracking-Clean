## Nachtrag: die „Löschen"-Schaltfläche trug dieselbe Kollision

Der **erste** Lauf des Messskripts (vor dem Nachtrag-Fix) maß für „Löschen" bei 600 × 900:
**40 × 28 px** mit wirksamer Polsterung `6px 12px` — exakt dieselbe Spezifitätskollision wie
„Korrigieren" vor dem Fix (dieselbe `size="sm"`-Klasse der `Button`-Primitive, dasselbe
`className="p-2 sm:px-3 sm:py-1.5"`-Muster). Gemäß Plan (Task 1, Scope Fence: „Halten sie
[„Löschen"] nicht, gehören sie zu demselben Befund … und werden mit behoben") wurde dieselbe
Korrektur (`!p-2 sm:!px-3 sm:!py-2`) angewendet und **erneut gemessen** — die Tabelle oben
zeigt bereits das Ergebnis **nach** diesem Nachtrag. Commit `afd1bdd`.

## Warum das `!`-Präfix und nicht `tailwind-merge`

`desktop/package.json` führt **keine** der folgenden Abhängigkeiten (geprüft,
`grep -c "tailwind-merge\|clsx\|classnames" package.json` → `0`):

- `tailwind-merge`
- `clsx`
- `classnames`

Die im Projekt bereits etablierte Lösung für exakt diesen Konflikt — eine lokale
Tailwind-Klasse, die von einer generischeren Klasse einer Primitive überschrieben wird — ist
Tailwinds `!`-Modifier. Bestandsvorbild:
`desktop/src/components/users/EditUserModal.tsx`, Zeile 908 (Stand 26.08.2026 — der Plan
zitiert Zeile 882; die Datei ist seither durch andere Pläne gewachsen, das Muster ist
dasselbe):

```tsx
className="bg-gray-100 dark:bg-gray-900 text-gray-600 dark:text-gray-400 cursor-not-allowed hover:!border-gray-300 dark:hover:!border-gray-600 hover:!shadow-sm"
```

Eine neue Abhängigkeit einzuführen wäre ein Werkzeugwechsel für einen Einzeiler gewesen —
nicht verhältnismäßig und außerhalb des Scopes von D-2 (Threat Register T-14.2-11-03).

## Prüfskript gegen die Rückkehr der Kollision

`desktop/src/components/worktime/workTimePeriodActionsSize.check.ts` prüft den **Quelltext**
(nicht die gerenderte Größe) auf:

1. `!p-2` im `className` der „Korrigieren"-Schaltfläche.
2. `!p-2` im `className` der „Löschen"-Schaltfläche (Nachtrag).
3. **Keine** Rückkehr der Kollisionsform (`p-2` ohne führendes `!`), außerhalb von Kommentaren.
4. `py-2` (nicht `py-1`) im `className` des Chips.
5. Der Kopfkommentar der geprüften Datei nennt `D-2` und die Ursache
   („Entdeckungsreihenfolge").

**Kommentarfilterung:** Der Begründungskommentar über der „Korrigieren"-Schaltfläche zitiert
die frühere Kollisionsform (`'p-2'` ohne `!`) wörtlich, um sie zu erklären. Ohne Filterung
würde dieses Zitat Prüfung 3 selbst zum Fehlschlag bringen. Das Skript entfernt deshalb VOR
dem Zählen alle Block- und Zeilenkommentare:
```typescript
function ohneKommentare(text: string): string {
  return text.replace(/\/\*[\s\S]*?\*\//g, '').replace(/\/\/.*$/gm, '');
}
```
