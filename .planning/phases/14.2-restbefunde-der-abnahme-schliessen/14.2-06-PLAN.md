Eine gemeinsame, private Hilfsfunktion in `exports.ts` und zwei Aufrufe — **ein** Commit.

**A — Hilfsfunktion `extractErrorMessage(response, fallback)`** (Name frei waehlbar, nicht
exportiert), die aus einer nicht-`ok`-Antwort die anzuzeigende Meldung gewinnt. Reihenfolge:

1. Den Koerper **einmal** als Text lesen und vorhalten (`response.clone().text()` nach dem
   Muster von `client.ts:99`; unterstuetzt die von `universalFetch` gelieferte Antwort kein
   `clone()`, wird stattdessen `await response.text()` gelesen und der Text anschliessend mit
   `JSON.parse` ausgewertet — der Koerper darf nur **einmal** konsumiert werden).
2. Den Text als JSON auswerten. Traegt das Ergebnis ein Feld `error` vom Typ `string` mit
   nicht-leerem Inhalt, ist **das** die Meldung.
3. Sonst — kein JSON, kein `error`-Feld, oder `error` ist keine nicht-leere Zeichenkette —
   wird der `fallback`-Satz zurueckgegeben, **erweitert um den HTTP-Statuscode**, damit der
   Vorgang nachvollziehbar bleibt. Der Rohtext wird **nicht** in die Meldung geschrieben; er
   geht ausschliesslich in eine `console.error`-Ausgabe, gekuerzt wie in `client.ts:104-107`
   (`rawTextPreview: rawText.substring(0, 200)`).

**Kein `any`.** Das Ergebnis von `JSON.parse` ist `unknown` und wird ueber eine Typwache
eingeengt (etwa `typeof parsed === 'object' && parsed !== null && 'error' in parsed &&
typeof parsed.error === 'string'`). Auf ein Feld `code` wird sich **nicht** gestuetzt — es
existiert nicht.
