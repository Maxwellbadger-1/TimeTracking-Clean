**A — Neues, nebenwirkungsfreies Modul `server/src/scripts/protectedTables.ts`.**
Es enthaelt genau vier oeffentliche Dinge und importiert **nur** `createHash` aus
`node:crypto` und den Typ `Database as BetterSqlite3Database` aus `better-sqlite3`
(reiner Typimport, `import type`):

- `export const PROTECTED_TABLES: readonly string[]` mit exakt den fuenf Namen
  `time_entries`, `absence_requests`, `overtime_corrections`, `vacation_balance`,
  `vacation_transactions` — Reihenfolge unveraendert aus `purgeFutureOvertimeRows.ts`,
  damit die Ausgabe zeilenweise mit den 14.1-Nachweisen vergleichbar bleibt.
- `export interface ProtectedMetric { table: string; rowCount: number; checksum: string }`
- `export function measureProtectedTables(db: BetterSqlite3Database): ProtectedMetric[]` —
  Rumpf **zeichengleich** zur heutigen lokalen Fassung: `SELECT * FROM ${table} ORDER BY id ASC`,
  SHA-256 ueber `JSON.stringify(rows)`. Das Verfahren darf sich nicht aendern, sonst sind die
  Werte nicht mit 14.1 vergleichbar.
- `export function printProtectedTables(label: string, metrics: ProtectedMetric[]): void` —
  Rumpf zeichengleich zur heutigen lokalen Fassung.
- zusaetzlich `export function formatProtectedTablesMarkdown(metrics: ProtectedMetric[]): string`
  — eine Markdown-Tabelle mit den Spalten `Tabelle | Zeilen | sha256`, damit die Werte ohne
  Nacharbeit in ein SUMMARY oder Nachweisdokument kopiert werden koennen.

Das Modul enthaelt **keinen** Top-Level-Code, der eine Datenbank oeffnet, und importiert
**nicht** `../database/connection.js`.

**B — `purgeFutureOvertimeRows.ts` auf das Modul umstellen (additiv, verhaltensgleich).**
