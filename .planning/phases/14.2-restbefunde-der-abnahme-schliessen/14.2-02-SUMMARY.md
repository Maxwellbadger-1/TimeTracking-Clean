## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Aufräumreihenfolge in `cleanupEmployee()` verletzte die FOREIGN-KEY-Kette über `audit_log`**
- **Found during:** Task 2, erster Testlauf (`npx vitest run src/routes/users.reactivate.test.ts`)
- **Issue:** Erste Fassung löschte `users` vor `audit_log`. `audit_log.userId` verweist per
  FOREIGN KEY auf `users(id)` **ohne** `ON DELETE CASCADE` (bekanntes Muster aus
  `workPeriodChangeService.test.ts`); der von der Route erzeugte `logAudit()`-Eintrag des
  Admin-Testnutzers blockierte dessen eigenes Löschen mit `SqliteError: FOREIGN KEY constraint
  failed`.
- **Fix:** Reihenfolge in `cleanupEmployee()` umgestellt — erst `DELETE FROM audit_log WHERE
  userId = ?`, danach `DELETE FROM users WHERE id = ?` (CASCADE räumt `user_work_periods`,
  `overtime_transactions`, `overtime_balance` automatisch ab und vermeidet damit auch den
  Löschguard-Trigger auf `user_work_periods`, siehe deferred-items.md Plan 14.1-03 Punkt 2).
- **Files modified:** `server/src/routes/users.reactivate.test.ts`
- **Verification:** Testlauf danach 5/5 grün; `SELECT COUNT(*) FROM users WHERE username LIKE
  'test-142-02-%'` liefert 0.
- **Committed in:** `dc3502c` (Teil des Task-2-Commits, kein separater Commit — Rule-1-Fix
  innerhalb desselben ungetesteten Entwurfs, nicht nachträglich an bereits committetem Code)

**2. [Rule 3 - Blocking] Laufender Server auf 127.0.0.1:3100 hatte den Fix aus Task 1 nicht geladen**
- **Found during:** Task 2, beim ersten Versuch, `sicht.p1228` über den echten Bedienweg zu
  reaktivieren — Antwort war noch der alte englische 404-Text, obwohl der Quelltext bereits
  den Fix trug.
- **Issue:** Der von Plan 14.2-01 gestartete Serverprozess läuft mit `npx tsx src/server.ts`
  (kein Watch-Modus) und lädt Quelltextänderungen nicht automatisch nach.
- **Fix:** Prozess auf Port 3100 identifiziert (`Get-NetTCPConnection -LocalPort 3100`, PID
  30696), beendet und mit identischem Kommando (`PORT=3100 DATABASE_PATH=./database/
  development.db NODE_ENV=development npx tsx src/server.ts`) neu gestartet.
- **Files modified:** keine Codeänderung, nur Prozess-Neustart
- **Verification:** `curl http://127.0.0.1:3100/api/health` → `{"status":"ok",...}`;
  Reaktivierung von `sicht.p1228` lieferte danach HTTP 200 mit dem erwarteten Datensatz.
- **Committed in:** kein Commit nötig (Betriebsereignis, keine Codeänderung)
